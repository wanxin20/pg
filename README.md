# GOS PostgreSQL 升级脚本

此仓库用于交付 GOS 数据库升级。应用仓库新增数据库迁移时，需要同时更新本仓库的增量脚本与执行说明；应用代码上传不代表数据库已经升级。

## 当前升级到 075：仅 SSO 登录

已完成 074 的 GOS 业务库使用 `server_upgrade_074_to_075.sql`。目标管理员为已通过 SSO 登录的 `01069355`（`liupw@haier.com`）。脚本先核对工号、邮箱、正常状态和 IAMA 绑定，才提升其超级管理员权限，并停用全部本地人员账号、清除本地密码、撤销旧会话。保留原用户 ID、项目归属和历史审计引用，不物理删除用户。其他 SSO 账号角色不变。

执行前备份实际业务库，停止 GOS 服务和写入进程，使用指向该库的现有安全连接配置执行：

```bash
psql -X -v ON_ERROR_STOP=1 -f server_upgrade_074_to_075.sql
```

核对目标账号为 `iama / super_admin / active`，`remaining_active_local_users` 为 0。然后更新仅 SSO 登录的后端及后台静态文件，启动服务，用该企业身份重新登录验证。不能先停旧管理员再核对新身份；本脚本失败时整个事务回滚。它不执行 073，不修改并发配置，也不修改上游 IAMA 密码。

此脚本是指定实例的账号交接，不用于其他环境的自动初始化。应用和独立前端副本的同步说明见应用仓库 `docs/SSO_ONLY_AUTH.md`。

开发验证可运行 `npm ci && npm run test:sso-only`，测试在独立内存 PostgreSQL 引擎中执行真实 SQL，覆盖身份不匹配、历史关联保留、幂等及中途失败回滚，不连接业务库。

## 前置升级到 074

已经完成 `server_upgrade_066_to_071.sql` 的数据库，执行 `server_upgrade_071_to_074.sql`。更早的库先按文件名顺序补齐前置升级，不对已有库重新执行初始化脚本。

本次包括：

- 072：新增诊断关联字段及索引。
- 074：新增本地密码策略所需的 6 个用户字段，从本地及 SSO 成功登录审计回填最近登录时间，不改现有密码哈希。

本升级包跳过 073，不调整子任务并发配置，也不要求先执行 073。文件名沿用 `071_to_074`，实际包含的迁移为 072、074。若此前已执行包含 073 的旧版升级包，更新文件不会自动恢复配置值，需要按实际需求在管理后台调整。

发布顺序：

1. 核对服务实际使用的数据库名与连接方式；沿用现有库，不按示例新建或替换数据库。
2. 停止 GOS 服务和相关写入进程，使用 `pg_dump -Fc` 备份该库并检查备份命令成功。
3. 在本仓库目录内，使用现有安全连接配置运行下列命令。连接配置应预先指向已核对的业务库，密码不放命令行或脚本。

   ```bash
   psql -X -v ON_ERROR_STOP=1 -f server_upgrade_071_to_074.sql
   ```

4. 确认退出码为 0、摘要为 `status=ok`、目标版本为 074、`included_migrations=072,074`，并返回全部 6 个用户字段。任何错误都停止发布；不要跳过错误继续重启。
5. 若本次继续升级到 075，接着执行上文的 075 交接及发布步骤；若仅部署历史 074 版本，则按该版本的依赖和发布说明验证登录、改密与 SSO。

脚本用单个事务执行；报错时本次升级回滚。已执行 072 或 074 的库可以重跑，较新的登录时间不会被旧审计覆盖。成功后的回退需结合备份和应用版本处理，不自动删除字段。

该脚本上传到 Git 不会自动连接或修改线上 PostgreSQL，必须在实际目标库执行。074 的字段保留供兼容；升级到 075 后本地账号退役，SSO 密码由上游认证系统管理。
